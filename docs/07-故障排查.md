# 故障排查

---

## 1. 安装脚本跑不起来

### `无法加载文件 install.ps1，因为在此系统上禁止运行脚本`

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

只对当前窗口生效，不会改系统策略。

### `git 不是内部或外部命令`

装 Git for Windows：<https://git-scm.com/download/win>，装完重开终端。

### Python 版本不对

`ansys-fluent-mcp` 需要 **Python 3.12+**。检查：

```powershell
py -0p
```

安装时指定解释器：

```powershell
.\install.ps1 -PythonExe "C:\Path\To\python.exe"
```

## 2. 技能装了但看不到

先确认你装的是哪个客户端——四个客户端的目录完全不同：

| 客户端 | 技能目录 |
|---|---|
| OpenCode | `~/.config/opencode/skills/<id>/SKILL.md` |
| Claude Code | `~/.claude/skills/<id>/SKILL.md` |
| Codex | `~/.agents/skills/<id>/SKILL.md`（**不是** `~/.codex/skills`） |
| Claude Desktop | 没有目录，只能应用内上传 zip |

### 通用检查顺序

1. 文件名必须是 `SKILL.md`（大小写敏感），不是 `skill.md` 或 `SKILL.md.txt`。
2. 目录名就是技能 ID，ID 大小写敏感。
3. frontmatter 必须有 `description`。
4. 是否被同名技能覆盖（后面的 source 覆盖前面的）。
5. 升级整合包后没加 `-Force`，旧版本还在原地。

手动验证：

```powershell
# 换成你实际用的客户端目录
Get-ChildItem "$env:USERPROFILE\.config\opencode\skills" -Directory |
  ForEach-Object { "$($_.Name) -> $(Test-Path (Join-Path $_.FullName 'SKILL.md'))" }
```

### OpenCode 专有

OpenCode 只列**有 description** 且**没有 `opencode/autoinvoke: false`** 的技能。`nature-shared` 被设为 `autoinvoke: false`，不会出现在列表里，这是正常的。重载：OpenCode 会自动监听文件变化；必要时 `/reload`。

### Codex 专有

- 目录写成 `~/.codex/skills` 是最常见的错误，那是配置目录，不存技能。
- 技能要在**启动 Codex 的目录**的祖先链上，或在用户级 `~/.agents/skills`。在 `D:\code` 里启动 Codex，`C:\Users\你\.agents\skills` 仍然可见。
- 用 `/skills` 打开列表确认，或直接打 `$journal-pipeline`。
- 同名技能不合并，两个都会出现在选择器里。

### Claude Desktop 专有

- 应用不读任何目录，装在磁盘上的技能它看不见，必须在 `Settings → Capabilities → Skills` 上传 zip。
- 上传失败先看 zip 结构：`SKILL.md` 要么在压缩包根目录，要么在一层同名文件夹里；两种都失败就手动重压（只压文件夹内容，不要带 `.DS_Store`、`__pycache__`）。
- 技能之间有引用关系，只传 `journal-pipeline` 而没传 `nature-writing` 之类，它会退化成凭内置能力硬写。

### Claude Code 专有

`~/.claude/skills/<id>/SKILL.md` 和 `~/.claude/commands/<name>.md` 都会产生同名 `/命令`。如果 `/paper` 没出现，先看 `~/.claude/commands/paper.md` 是否存在，再看 `claude` 会话里 `/help` 是否列出。

## 3. MCP 连不上

### 先确认命令本身能跑

```powershell
& "C:\...\sci-research-pack\.venv\Scripts\ansys-fluent-mcp.exe" --help
& "C:\...\sci-research-pack\.venv\Scripts\origin-pro-mcp.exe" --help
```

如果这里就报错，先修 Python 包，不要改 MCP 配置。

### OpenCode 配置形状

V2 必须放在 `mcp.servers` 下：

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "ansys-fluent": {
        "type": "local",
        "command": ["C:\\...\\ansys-fluent-mcp.exe"]
      }
    }
  }
}
```

常见错误：

- 写成 `"mcp": { "ansys-fluent": {...} }`（V1 形状）。
- 把 `command` 写成字符串而不是数组。
- Windows 路径没转义反斜杠。
- 用 `~` 而不是绝对路径（MCP 启动不经过 shell）。

### 查看状态

```powershell
opencode mcp list
```

或在 OpenCode 里 `/mcps`。

### Claude Code

```powershell
claude mcp list
claude mcp add --scope user ansys-fluent -- "C:\...\ansys-fluent-mcp.exe"
```

`--scope user` 写进 `~/.claude.json`；`--scope project` 写进当前仓库的 `.mcp.json`（这个文件通常会被提交，别把本机绝对路径推上去）。

### Codex

`~/.codex/config.toml`（Windows 是 `C:\Users\<你>\.codex\config.toml`）：

```toml
[mcp_servers.ansys-fluent]
command = 'C:\...\ansys-fluent-mcp.exe'
args = []
startup_timeout_sec = 45
tool_timeout_sec = 600
```

注意：

- 用**单引号**，Windows 反斜杠不用转义。写成双引号又不转义是最常见的解析错误。
- `tool_timeout_sec` 别用默认值。Fluent 求解是分钟级，默认超时会在求解中途断开。
- 检查：`codex mcp list`。
- 整块是 `[mcp_servers.ansys-fluent]` 加 `[mcp_servers.ansys-fluent.env]` 两个表；只删主表会留下孤立的 `.env` 表，导致 TOML 解析失败。

### Claude Desktop

配置文件位置：

| 系统 | 路径 |
|---|---|
| Windows | `%APPDATA%\Claude\claude_desktop_config.json` |
| macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Linux | `~/.config/Claude/claude_desktop_config.json` |

```json
{
  "mcpServers": {
    "ansys-fluent": {
      "command": "C:\\...\\ansys-fluent-mcp.exe",
      "args": [],
      "env": { "FLUIDS_MCP_LOG_LEVEL": "INFO" }
    }
  }
}
```

三个专有坑：

1. 键是 `mcpServers`，不是 OpenCode 的 `mcp.servers`，也没有 `type` 字段。
2. 改完**必须从托盘退出**再重开。关窗口只是收进托盘，进程还在，配置不会重载。
3. JSON 不允许注释。带 `//` 会直接导致整个配置被忽略，且应用不报错。

### 四个客户端共用的问题

- 路径写 `~`：MCP 启动不经过 shell，`~` 不会展开，必须绝对路径。
- `command` 写成字符串数组（OpenCode 是数组，其他三个是字符串）——别抄错。
- `.venv` 被删或换机器后路径变了，四个客户端会一起失效；重跑 `-WithFluent`（装了 Origin 的再加 `-WithOrigin`）。

## 4. Fluent 相关错误

### `connect` 失败 / 找不到 Fluent

- 本机必须安装 Fluent，且 `ansys-fluent-core` 能找到安装路径。
- 设置环境变量：

```powershell
$env:AWP_ROOT261 = "C:\Program Files\ANSYS Inc\v261"
```

（版本号按你的安装改：v251 / v252 / v261…）

### `License` 相关报错

- Fluent 是**独占 license**。确认没有别人占满。
- 检查 license 服务器：

```powershell
$env:ANSYSLMD_LICENSE_FILE
```

- 不要在未授权的情况下让 Agent 反复 `connect`；每次失败也可能占用/释放 license。

### 版本不匹配

`ansys-fluent-core` 的版本要与 Fluent 版本匹配。查：

```powershell
pip show ansys-fluent-core
```

必要时固定版本：

```powershell
pip install "ansys-fluent-core==0.27.*"
```

### `run_code` 执行任意 Python 的风险

- 只运行你读过的代码。
- 不要在生产会话里开 `PYFLUENT_MCP_ENABLE_PYTHON=1`。
- 不要让 Agent 把未审阅的模型输出直接粘进 `run_code`。

## 5. Origin 相关错误

`origin-pro` 走 COM，故障几乎都出在「Origin 这一侧」，而不是 MCP 这一侧。先按顺序查：

```powershell
.\verify.ps1                       # 看 [Origin Pro] 段
Get-Item 'Registry::HKEY_CLASSES_ROOT\Origin.ApplicationSI'
Get-Process Origin64, Origin -ErrorAction SilentlyContinue
```

### `Dispatch` 失败 / `Invalid class string` / COM 报错

- Origin 没启动。**MCP 不会替你启动 Origin**，先手动打开。
- Origin 装的是 32 位版，Python 是 64 位（或反过来）。两者位数必须一致；现在的 OriginPro 2020+ 默认 64 位，Python 也要 64 位。
- 装的是 Origin Viewer 而不是 OriginPro。Viewer 没有 COM 自动化接口。
- 注册表里没有 `HKCR\Origin.ApplicationSI` 就是没注册成功，重装或修复 Origin。

### 工具调用卡住不返回

Origin 弹了模态对话框——保存提示、许可证过期、更新提醒、脚本错误框。MCP 在等 COM 返回，对话框不点掉就永远等下去。

处理：切到 Origin 窗口把对话框点掉；如果窗口被遮住，用任务栏缩略图找。之后重试该工具，不要连续重发。

### 导出的文件是 0 字节 / 找不到文件

- `graph_name` 写错。Origin 的对象名区分大小写，`Fig1A` ≠ `fig1a`。
- 图页还没生成就导出。先 `list_worksheets` 或 `run_labtalk` 确认对象存在。
- 导出路径的目录不存在。`export_graph` 不会替你建目录，先 `New-Item -ItemType Directory`。

### 中文变方框 / 字体不对

Origin 默认字体不含中文字形。先 `set_graph_font` 指定宋体或思源黑体，再导出。数字和拉丁字母仍建议走 Arial。

### 样式只改了一个图

Origin 的样式是**逐图页**的，`apply_publication_style` 不会广播到所有图。多面板图要对每个 `Fig1A` / `Fig1B` 分别调用，且参数保持一致。

### `new_project` 之后原来的工程没了

`new_project` 关闭当前工程且不保存。调用前必须确认没有未保存的工作；MCP 不会弹保存提示。

### `pip install` 阶段报 `mcp` 版本冲突

`ansys-common-mcp` 要 `mcp<3` + `fastmcp>=3`（后者要 `mcp>=2.3`），Origin 上游代码写的是 1.x 的 `mcp.server.fastmcp`。本包已用双版本导入兼容，正常情况下不该出现冲突。

如果确实报了，先确认装的是包内源码而不是 PyPI 上的旧版：

```powershell
.\.venv\Scripts\python.exe -m pip show origin-pro-mcp
.\.venv\Scripts\python.exe -m pip install --upgrade .\mcp\origin-pro
```

不要执行 `pip install "mcp<2"`——那会让 Fluent MCP 的 `fastmcp` 装不上。

## 6. GitHub 访问不稳定

安装脚本默认 `git clone`。如果失败：

1. 用镜像前缀：

```powershell
git clone --depth 1 https://gh-proxy.com/https://github.com/OWNER/REPO.git
```

2. 或先手动下载 zip，解压到 `vendor/<name>`，再运行：

```powershell
.\install.ps1 -SkipClone
```

3. 本包的 42 个技能已经**内置**在 `skills/vendor/`，不联网也能安装；只有 `-WithARS` 和可选 MCP 需要联网。

## 7. 技能太多，Agent 选错

- 用 `journal-pipeline` 作为入口，它会按阶段只叫一个专家技能。
- 如果还是冲突，把不用的技能目录移出 `skills/`（或改名为 `.disabled`）。
- 不要同时装两个 ID 相同的技能。

查看当前技能清单：

```powershell
.\verify.ps1
```

---

## 8. 中文乱码

- `install.ps1` 已设置 UTF-8 输出。
- 如果终端仍乱码：

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8
chcp 65001
```

- Word 排版用 `nature-paper2word`，不要手工调中文字体。

```powershell
.\uninstall.ps1
```

只删除本包安装的技能与命令，不动你原有的配置。删除前会列出清单并要求确认。
