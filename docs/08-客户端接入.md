# 客户端接入：OpenCode / Claude Code / Codex / Claude Desktop

四个客户端对「技能」「斜杠命令」「MCP」的支持并不一样。装错目录是这套包里最常见的失败原因，所以先把差异列清楚。

---

## 0. 能力矩阵

| | 技能（SKILL.md） | 自定义斜杠命令 | MCP |
|---|---|---|---|
| **OpenCode** | 有目录，`~/.config/opencode/skills/<id>/SKILL.md` | 有目录，`~/.config/opencode/commands/<name>.md` | `opencode.json` → `mcp.servers.<name>` |
| **Claude Code** | 有目录，`~/.claude/skills/<id>/SKILL.md` | 有目录，`~/.claude/commands/<name>.md` | `claude mcp add --scope user`，存进 `~/.claude.json` |
| **Codex CLI** | 有目录，`~/.agents/skills/<id>/SKILL.md` | **没有**自定义命令目录 | `~/.codex/config.toml` → `[mcp_servers.<name>]` |
| **Claude Desktop** | **没有**目录，只能上传 zip | **没有** | `%APPDATA%\Claude\claude_desktop_config.json` → `mcpServers` |

三个容易踩的点，先记住：

1. **Codex 的用户级技能目录是 `~/.agents/skills`，不是 `~/.codex/skills`。** 后者是配置目录（`config.toml` 在那儿），不存技能。
2. **Codex 没有 `~/.codex/prompts` 这种自定义命令机制。** 技能靠 `/skills` 列表或 `$技能名` 调用。
3. **Claude Desktop 是 GUI，不读任何技能目录。** 技能必须在应用内 `Settings → Capabilities → Skills` 逐个上传 zip，装脚本只能替你把 zip 打包好。

---

## 1. 一条命令装好

```powershell
# 只装 OpenCode（默认）
.\install.ps1

# 一次装多个客户端
.\install.ps1 -Clients opencode,claude,codex

# 连 Claude Desktop 的 MCP 一起配（技能仍要手动上传 zip）
.\install.ps1 -Clients opencode,claude-desktop -WithFluent

# 同时装 Origin MCP（仅 Windows，需 OriginPro 2020+）
.\install.ps1 -Clients opencode,claude,codex -WithOrigin
```

```bash
./install.sh --clients opencode,claude,codex --with-fluent
```

`-Clients` 的合法取值就是上表那四个：`opencode`、`claude`、`codex`、`claude-desktop`。可以任意组合，重复的会被忽略。

脚本对每个客户端做的事：

| 客户端 | 技能 | 命令 | MCP |
|---|---|---|---|
| `opencode` | 复制到 `~/.config/opencode/skills/` | 复制到 `~/.config/opencode/commands/` | `opencode mcp add`，失败则合并 JSON |
| `claude` | 复制到 `~/.claude/skills/` | 复制到 `~/.claude/commands/` | `claude mcp add --scope user` |
| `codex` | 复制到 `~/.agents/skills/` | 跳过 | 向 `~/.codex/config.toml` 追加 TOML 块 |
| `claude-desktop` | 打包成 `dist/claude-skills/<id>.zip` | 跳过 | 合并 `claude_desktop_config.json` |

已存在的技能目录默认不覆盖，要替换加 `-Force`（bash 为 `--force`）。

## 2. OpenCode

### 路径

```
~/.config/opencode/
├── opencode.json          # MCP 在 mcp.servers 下
├── skills/<id>/SKILL.md
└── commands/<name>.md
```

Windows 上 `~` 是 `C:\Users\<你>`。项目级可以放在仓库里的 `.opencode/skills/` 和 `.opencode/commands/`，优先级高于全局。

### 调用

```
/paper        论文主线
/cfd          CFD 主线
```

这两条命令是给 agent 的入口指令，内部会路由到 `journal-pipeline` / `cfd-fluent-pipeline`。技能不用手动点名，描述匹配就会自动加载。

### 验证

```powershell
opencode mcp list          # MCP 是否注册
```

会话里输入 `/mcps` 看 MCP 状态、`/skills` 类似入口看技能。`nature-shared` 设了 `autoinvoke: false`，不会出现在技能列表里，这是正常的。

### MCP 配置形状

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "ansys-fluent": {
        "type": "local",
        "command": ["C:\\path\\to\\ansys-fluent-mcp.exe"]
      }
    }
  }
}
```

V1 的 `"mcp": { "ansys-fluent": {...} }` 形状在 V2 下无效，这是最常见的「配了但连不上」。

## 3. Claude Code

### 路径

```
~/.claude/
├── skills/<id>/SKILL.md
└── commands/<name>.md
```

项目级：`<repo>/.claude/skills/`、`<repo>/.claude/commands/`。

Claude Code 里技能和命令是同一套东西：`.claude/commands/deploy.md` 和 `.claude/skills/deploy/SKILL.md` 都会产生 `/deploy`。本包两者都装，所以 `/paper`、`/cfd` 直接可用；技能目录额外提供 `description`，让模型能自动挑。

### MCP

```powershell
claude mcp add --scope user ansys-fluent -- "C:\path\to\ansys-fluent-mcp.exe"
claude mcp list
```

`--scope user` 写进 `~/.claude.json`，对所有项目生效。项目级用 `--scope project`，会生成 `.mcp.json`（这个文件通常会提交进仓库，注意别把本机绝对路径推上去）。

会话内 `/mcp` 可以看连接状态。

## 4. Codex CLI

### 路径

| 作用域 | 位置 |
|---|---|
| 用户 | `$HOME/.agents/skills/`（Windows：`C:\Users\<你>\.agents\skills\`） |
| 仓库 | 从当前目录一路向上到仓库根的每一层 `.agents/skills/` |
| 管理员 | `/etc/codex/skills`（Linux/macOS） |

同名技能不会合并，两个都会出现在选择器里，所以别在同一台机器上重复装同一份。

### 调用

```
/skills                 打开技能列表，选 journal-pipeline
$journal-pipeline       直接点名调用
$                       只打一个美元符号会弹补全
```

Codex 没有自定义斜杠命令目录，所以本包的 6 个命令文件对 Codex 不生效——这不影响使用，`journal-pipeline` 和 `cfd-fluent-pipeline` 的 SKILL.md 里已经写了完整的六道门/七道门流程，直接调用技能等价于跑 `/paper`、`/cfd`。

### MCP

安装脚本会往 `~/.codex/config.toml` 追加：

```toml
[mcp_servers.ansys-fluent]
command = 'C:\path\to\ansys-fluent-mcp.exe'
args = []
startup_timeout_sec = 45
tool_timeout_sec = 600

[mcp_servers.ansys-fluent.env]
FLUIDS_MCP_LOG_LEVEL = "INFO"
FLUIDS_MCP_MAX_STEPS = "30"
```

TOML 的字面量字符串用单引号，Windows 反斜杠**不用**转义，这是它比 JSON 省事的地方。手动改配置时最容易错的是用双引号又不转义，`'C:\Program Files\...'` 才对。

验证：

```powershell
codex mcp list
```

`tool_timeout_sec` 给到 600 秒是因为 Fluent 求解本身就是分钟级，默认超时会在求解中途把连接掐掉。

## 5. Claude Desktop

Claude Desktop 跟另外三个不是一个物种：它是 GUI 应用，**不读技能目录、不支持自定义斜杠命令**，只认一个 MCP 配置文件。

### 5.1 MCP 配置位置

| 系统 | 路径 |
|---|---|
| Windows | `%APPDATA%\Claude\claude_desktop_config.json` |
| macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Linux | `~/.config/Claude/claude_desktop_config.json` |

形状跟 OpenCode 不同，键是 `mcpServers`，且没有 `type`：

```json
{
  "mcpServers": {
    "ansys-fluent": {
      "command": "C:\\path\\to\\ansys-fluent-mcp.exe",
      "args": [],
      "env": {
        "FLUIDS_MCP_LOG_LEVEL": "INFO",
        "FLUIDS_MCP_MAX_STEPS": "30"
      }
    }
  }
}
```

脚本会先备份成 `claude_desktop_config.json.bak-<时间戳>`，再合并；已有其他 MCP 条目不会被删。

**改完必须从托盘退出再重开。** 关窗口只是收进托盘，进程还在，配置不会重新加载——这是「改了没用」的头号原因。

### 5.2 技能：只能上传 zip

Claude Desktop 的技能入口在应用内：

```
Settings → Capabilities → Skills → Upload skill
```

（部分版本写作 `Features → Skills`，入口同名。）

装脚本时带 `-Clients claude-desktop` 会预先把技能打包成 `dist\claude-skills\<id>.zip`，一个技能一个包，解压后结构是：

```
journal-pipeline/
└── SKILL.md
```

上传时按需挑，不用 44 个全传。建议的最小集合：

| 用途 | 上传这几个 |
|---|---|
| 论文主线 | `journal-pipeline` + `paper-workflow` + `sciwrite` |
| 投稿前检查 | `submission-audit` + `citation-verifier` + `stats-reporting-audit` |
| 图 | `figure-planner` + `nature-figure` |
| Origin 图 | `origin-pro`（另需 MCP 一起配） |
| CFD | `cfd-fluent-pipeline` + `fluent-cfd` |

技能之间会互相引用（比如 `journal-pipeline` 会调用 `nature-writing`），上传时最好把被引用的也一起传，否则它会退化成用内置能力硬写。

> 上传失败时先看 zip 结构：有的版本要求 `SKILL.md` 在压缩包**根目录**，而不是套一层同名文件夹。把文件夹里的内容重新压一次即可。

### 5.3 命令

没有。要跑论文主线就在对话里直接说，例如：

```
用 journal-pipeline 流程帮我搭这篇论文的骨架，目标期刊 Nature Communications。
```

技能靠 `description` 匹配，正常情况下不用点名。

## 6. Origin MCP（可选，仅 Windows）

`origin-pro` 是第二个可选 MCP，用来驱动 OriginPro 画图、排版、拟合、导出。它跟 Fluent MCP 有三点不同：

1. **只在 Windows 可用。** 它走 COM 调 Origin，macOS/Linux 没有对应接口；`install.sh --with-origin` 在非 Windows 上会直接跳过。
2. **必须先手动打开 OriginPro。** MCP 只连接正在运行的实例，不会替你启动。调用 `new_project` 会清空当前会话，脚本不会替你判断有没有未保存的工程。
3. **源码在包内。** `mcp/origin-pro/` 是 vendored 的 0.2.0，`pip install` 读本地目录，不联网。

```powershell
.\install.ps1 -WithOrigin -Clients opencode,claude,codex,claude-desktop
```

注册结果（MCP 名固定为 `origin-pro`）：

| 客户端 | 写到哪里 |
|---|---|
| OpenCode | `opencode mcp add origin-pro`，或 `opencode.json` → `mcp.servers.origin-pro` |
| Claude Code | `~/.claude.json` → `mcpServers.origin-pro` |
| Codex | `~/.codex/config.toml` → `[mcp_servers.origin-pro]` |
| Claude Desktop | `claude_desktop_config.json` → `mcpServers.origin-pro` |

验证：

```powershell
opencode mcp list            # 或 codex mcp list / claude mcp list
.\verify.ps1                 # 看 [MCP: origin-pro] 和 [Origin Pro] 两段
```

`verify.ps1` 会额外检查 COM 注册项 `HKCR\Origin.ApplicationSI` 和 Origin 进程。COM 没注册说明 Origin 没装好或位数不对，这时 MCP 一定连不上。

> 依赖上有一个坑：`ansys-common-mcp` 要求 `mcp<3` 且 `fastmcp>=3`，后者要求 `mcp>=2.3`；而 Origin 上游代码写的是 1.x 的 `mcp.server.fastmcp`。本包在 `mcp/origin-pro/src/origin_pro_mcp/app.py` 做了双版本导入，两条 SDK 线都能起。**不要**为了迁就 Origin 把 `mcp` 钉回 1.x，那会让 Fluent MCP 装不上。

## 7. 验证

```powershell
# 装了什么就验什么
.\verify.ps1 -Clients opencode,claude,codex,claude-desktop
```

脚本按客户端分别检查：技能目录里 17 个核心技能是否齐、命令文件数量、MCP 是否写进对应配置文件、Claude Desktop 的 zip 是否生成、venv 里 `ansys-fluent-mcp` / `origin-pro-mcp` 装没装、Fluent 安装根目录和许可证变量、Origin 的 COM 注册与进程。

只关心某一个客户端时：

```powershell
.\verify.ps1 -Clients codex
```

bash 环境没有 `verify` 脚本，直接看目录：

```bash
ls ~/.agents/skills | wc -l
grep -A3 'mcp_servers.ansys-fluent' ~/.codex/config.toml
grep -A3 'mcp_servers.origin-pro' ~/.codex/config.toml
```

## 8. 卸载

```powershell
.\uninstall.ps1 -Clients opencode,claude,codex
```

只删本包装进去的技能目录和命令文件，不动别的技能、不动 MCP 配置、不删 `.venv` 和文稿。MCP 条目要单独清：

| 客户端 | 清 MCP |
|---|---|
| OpenCode | `opencode mcp remove ansys-fluent`（Origin 再加一条 `opencode mcp remove origin-pro`） |
| Claude Code | `claude mcp remove ansys-fluent`（Origin：`claude mcp remove origin-pro`） |
| Codex | 删 `~/.codex/config.toml` 里的 `[mcp_servers.ansys-fluent]` 和 `[mcp_servers.origin-pro]` 整块（含各自的 `.env` 子表） |
| Claude Desktop | 删 `claude_desktop_config.json` 里的 `mcpServers.ansys-fluent` 和 `mcpServers.origin-pro` |

Claude Desktop 里已上传的技能只能在应用内逐个删除，脚本碰不到。

## 9. 换机器 / 多客户端共存

四个客户端的技能目录互不干扰，可以同时装。共用的是 `skills/vendor` 源目录和 `.venv`，所以：

- 同一台机器装多个客户端，磁盘上会有多份技能副本（每个几 MB，可接受）。
- `.venv` 只有一份，四个客户端的 MCP 配置都指向同一个 `ansys-fluent-mcp.exe`（和可选的 `origin-pro-mcp.exe`）。删掉 `.venv` 四个客户端一起失效。
- 升级整合包后要重跑安装并加 `-Force`，否则旧技能不会被覆盖。
